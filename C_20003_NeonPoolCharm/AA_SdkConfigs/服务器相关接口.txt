一、唯一真实的服务器接口（third/CoinfinityRideress.ts）
Base URL：https://game.poolquestfun.online，自定义请求头携带包名、版本、设备 UUID、语言、系统、网络类型等。返回协议是 {code: 0=成功, data, mimickers=错误信息}。
1. GET /api/user/kickstart — 启动配置（geomUndefinablenessUnunitable，:359）
启动时拉取，失败 1 秒后无限重试。返回 data 各字段含义：
字段
含义
cyber
运行模式标志 → intranet。0 = 正式模式（需走 panel 远程资源流程）；非 0 = 内网/审核模式
panel
AES 加密，解密后 {domain[], path, options}：远程资源/热更的域名列表+路径，带备用域名轮询（domainindex 记录可用域名）
coding

spawn / dragons

IP_RESTRICT / VPN_RESTRICT

layered/strategy/mercy/exploit
4 个埋点上报开关，分别控制 700-799、330-399、500-599、100-299 号段的状态码是否允许上报
2. POST /client/data-log — 埋点/日志上报（leporidMoldedConstrained，:421）
两种 body：
•
{empire: {plugin: 状态码, search: 附加信息}} — 启动流程状态码（300=初始化、305=登录成功、308=A/B 进新球杆流程、314=资源加载完成、702/701=域名加载成功/失败等）
•
{crossfire: [...]} — AES 加密的事件记录批量上传，本地先存 __league__，90 秒定时或满 20 条 flush
3. POST /api/v4/readout/page（labioglossopharyngeal）
已封装但无任何调用点，死代码。
4. 远程资源加载（非 API）
用 kickstart 下发的 panel.domain[i] + panel.path 通过 cc.assetManager.loadAny 加载远程 bundle/热更资源，失败依次轮询备用域名。

三、其他"看似联网"实际无效的
•
SdkHelper.reportData（SdkHelper.ts:300）：空函数，所有 app_start/pay/level_statis 等埋点全是 no-op
•
FrameSDK.HttpGet（FrameSDK.ts:172）：定义了但无调用点
•
PoolWrapper/PoolNative：广告聚合 SDK 原生桥，广告请求在原生层完成，JS 层不可见
•
SuperReward 任务墙、openWeb 的 H5 链接（zephyrona.com、vortexiax.com）：WebView 加载外链页面，非接口调用
总结：这个包对外只有 game.poolquestfun.online 的 kickstart 配置下发和 data-log 埋点上传两个真实接口，加一套远程资源域名热更；玩法相关的"服务器"全部是本地 LocalServer 模拟的。
